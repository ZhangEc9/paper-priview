# 下一步：从单任务训练走到两任务顺序学习

日期：2026-11-03。当前仍用公司电脑 CPU；不需要 GPU，也不用先安装 Meta-World。

## 这次要理解的三个问题

1. 学过 A 的策略，没训练过 B 时，在 B 上表现怎样？这是直接迁移的初步观察。
2. 继续训练 B 以后，回到 A 表现是变差、保持，还是提高？不要提前假设一定遗忘。
3. B 从零学与接着 A 学有什么差别？先比较结果，再结合曲线讨论学习速度。

今天建议先花 60—90 分钟完成本练习；不再把整天都用于通读库源码。

## 1. 两个任务怎样定义

- A：Pendulum-v1，重力参数 g=10。
- B：同一环境，g=5。
- 观测维度、动作维度和奖励公式保持一致，环境动力学发生变化。
- 策略输入不附带任务编号，也不直接告诉它 g。评估器知道在哪个环境中测量。

两者很接近，可能共用一个有效策略。因此这里适合学习任务切换和评估方法，不是刻意制造遗忘，也不代表标准机器人 CRL benchmark。如果换 g，记录变更；不要为了看到掉分而反复挑参数。

## 3. 读懂输出矩阵

打开 `runs/my_two_tasks_10k/evaluation_matrix.csv`：

| 行 | A列 | B列 |
|---|---|---|
| random | 随机策略在A的回报 | 随机策略在B的回报 |
| after_A | 学完A后，在A评估 | 学完A后，尚未训练B，在B评估 |
| after_A_then_B | 同一模型接着学完B，在A评估 | 同一模型接着学完B，在B评估 |
| scratch_B | 从零学B后，在A评估 | 从零学B后，在B评估 |

每个单元格都实际调用独立环境评估；随机和模型评估使用同一组固定初始状态。开发曲线用另一组初始状态，不用于选模型。`after_A` 和 `after_A_then_B` 才是顺序学习矩阵的两行，其他两行是参考。

先分别比较每个任务，不急着把两个任务的原始回报平均。动力学改变也会影响任务难度和回报分布。

`summary.json` 给出：

- `A_return_drop_after_B = 学完A时的A回报 - 学完B时的A回报`。正数表示本次A回报下降，负数表示提高。先看A最初是否学好，单次下降不能直接推出稳定的灾难性遗忘。
- `B_final_return_difference_vs_scratch`：顺序训练与从零训练在B上的最终回报之差。它只是等量B交互预算下的终点比较，不等于标准前向迁移指标，也不代表顺序方案总训练成本更少。
- `timing`：三段实际训练时间及更新次数。

`after_A_curve.csv`、`after_A_then_B_curve.csv`、`scratch_B_curve.csv` 保存开发曲线原始数据；三个zip是对应模型。今天不要求画复杂图或多种子验证。

## 4. 这次重点读代码的地方

打开 `two_task.py`：

1. `make_model()`：确认和昨天使用的SAC配置相同。
2. `main()` 内 `after_a = evaluate_both(...)`：A训练后也测B，尚未用B训练数据。
3. **任务切换三行是重点：**

```python
sequential.set_env(env_b, force_reset=True)
sequential.replay_buffer.reset()
timing_b = train_phase(sequential, ...)
```

这里复用同一个模型对象，保留actor、critic、target网络、优化器和熵系数的状态；经验池逻辑清空，所以B阶段不会抽到A经验。这是本练习定义的“整套SAC状态顺序微调”，还没有实现抗遗忘方法，也没有隔离成只迁移actor。

`train_phase()` 用 `reset_num_timesteps=True` 重置阶段步数并重新经历500步随机探索；这个开关不重新初始化网络。两段B训练都有相同的步数和随机探索长度，独立B使用相同初始化种子；由于策略和历史不同，交互轨迹并不相同。

4. `independent = make_model(...)`：这里才创建全新模型，作为B从零训练对照。
5. `evaluate_both()` 和矩阵生成：评估不会用回报调整策略，也不把测试环境访问拿来选择超参。

先别改清空经验池这一行。直接混入旧环境数据会改变实验协议，后续若做历史回放，需要明确任务区分与动力学混合带来的影响。
