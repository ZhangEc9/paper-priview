## 2. CPU能复现到哪一步

官方 `experiments/meta-world/run_sac.py` 已实现无CUDA时选择CPU。Meta-World的低维状态输入配MLP不要求GPU；MuJoCo也可在CPU执行物理仿真。

依次推进：

1. 独立环境安装兼容的Meta-World与MuJoCo，锁定作者使用的Meta-World commit；先reset/step，无需画面。
2. 官方simple单任务短跑：验证网络更新、环境结束、评估、保存和加载。原默认随机探索10000步、开始更新5000步，短跑参数若改变要单独记录。
3. CKA-RL短任务序列：验证基础模型、向量组合、系数梯度及向量保存；使用小池容量，让历史向量数量实际超过容量并检查合并发生。按日志确认，不凭任务数猜测。
4. 测量稳定训练、评估耗时及内存，再决定是否恢复论文完整规模或回学校使用GPU。

每任务百万步、多任务、多个训练种子的论文结果复现不能承诺在公司CPU迅速完成。不同基准之间的SAC吞吐也不能直接互相外推。

忠实复现原方法、修复运行兼容性、增加周期评估、提出新合并机制应分开记录；由实现缺陷修复带来的差异不作为新方法收益。

## 3. 先把“旧知识”影响的对象说清楚

官方代码逐任务保存策略模块，同时把知识池传给后续任务。知识池压缩对未来任务的知识复用和适应速度尤其重要。保留的旧策略文件如果不被改写，其本身不会因为知识池合并自动遗忘。

因此后续必须核对原论文中不同评估协议和代码：是拿各任务保存的策略测，还是用最终共享系统测？合并效果应优先检查新任务学习曲线、前向迁移和池资源，不能仅用一个已保存旧模型的回报判断。

## 4. 候选：保持历史组合贡献的合并

### 动机

余弦相似度描述方向，平均值对两个向量等权。若历史任务对二者的实际组合比例不等，等权代表向量可能改变原来的贡献。

想研究的不是“余弦平均很差”，而是：**当历史使用模式有规律时，这些信息能否让合并更适合后续复用？**

### 必须成立的建模条件

先在同一个、明确对齐的知识池坐标下讨论。某些已完成任务或训练快照具有实际可记录的非负系数a_t、b_t，对应两个向量v_i、v_j的贡献：

    c_t = a_t v_i + b_t v_j。

合并后保留一个向量u，并把对应系数合为a_t+b_t，希望：

    c_t ≈ (a_t+b_t)u。

提出参数空间的代理目标：

    E(u) = Σ_t ||a_t v_i + b_t v_j - (a_t+b_t)u||²。

这是普通最小二乘建模。它保证的至多是所记录组合的重建误差，**不是策略行为、未来任务或回报保证**。

### 闭式解

设D=Σ_t(a_t+b_t)²>0，则：

    u* = w* v_i + (1-w*)v_j，
    w* = Σ_t(a_t+b_t)a_t / D。

若所有任务都按9:1组合，u*=0.9v_i+0.1v_j可精确保留这部分贡献；等权平均一般不能。若始终等权使用，最优权重退化到1/2。

如果D=0，记录中这两个向量都未被使用；目标不确定唯一代表，需规定明确的回退规则，不能除零。

### 只保留小型统计量

令Cii=Σa_t²、Cjj=Σb_t²、Cij=Σa_tb_t，有：

    D = Cii + 2Cij + Cjj，
    w* = (Cii + Cij)/D，
    E(u*) = ||v_i-v_j||² (Cii Cjj - Cij²) / D。

这显示误差同时涉及参数距离和系数使用规律。可以先用余弦选对、只改代表向量；若结果有价值，再考虑用该代价选合并对象。第一版不要两处同时改，以便解释增益来源。

闭式解属于标准最小二乘推导，不是新的数学定理。已用合成非负系数验证其数值等式；尚未接入CKA-RL，也未证明历史代理可预测未来收益。

## 5. 真正的难点与否定条件

1. **历史统计的坐标是否一致。** 不同任务看到的知识池会增长或发生合并，旧系数不能不经映射直接拼到当前池。需要定义合并映射及统计更新；早期没有的向量、已被合并的向量都要正确处理。
2. **历史使用能否预测未来。** 新任务组合权重还会重新学习，历史重建误差下降未必帮助新任务。如果没有收益，就停止这条具体思路。
3. **统计开销。** 记录完整历史系数会增长；若采用K×K的二阶统计，也要计入实际存储并处理容量变化。
4. **训练阶段权重的代表性。** 最终系数还是训练过程快照，需事先约定；不能看测试成绩后挑记录方式。
5. **与已有方法区别。** 需要查使用感知合并、加权原型、模型合并、MoE专家合并、任务向量压缩。当前不能承诺新颖性。

## 6. 最小对照与继续条件

先比较：

- 官方余弦选对＋等权平均。
- 相同选对＋按累计合并成员数量加权（简单强对手）。
- 相同选对＋上述历史系数重建权重。

在相同任务序列、交互预算、知识池容量下记录新任务学习曲线、最终表现、合并耗时及持久状态。新增历史信息和统计存储要单列；必要时给对手同等额外预算。

只有当历史系数规律确实存在，且代理误差改善能带来可重复的学习收益，才进入进一步方法设计。若简单成员数加权已足够，或所有权重近似1/2，就没有理由把本候选继续复杂化。

## 7. 与两份毕设的接口

主修：组合误差目标、最小二乘解、统计量更新、特殊情形及数值分析。

辅修：现成CRL框架复现、知识池状态、合并实现、迁移与资源评估。
